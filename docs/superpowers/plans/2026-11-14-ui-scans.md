# UI Scans Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/scans` page to `kubedelos ui`. It has:
- a start-scan form;
- one in-process scan at a time, with live HTMX progress and cancel;
- a paged run history;
- safe cleanup of `running` rows that no live process owns.

**Architecture:**
- **Run ownership:** every scan, from the CLI or the UI, holds an OS file lock named after an owner token stored on its
  run row (migration 6). A `running` row whose lock can be taken has no live owner.
- **Background scans:** the UI runs `run_scan` on a background thread owned by a `ScanRunner` held in `app.state`.
- **Progress:** `/scans/progress` returns a fragment that HTMX polls every 2 seconds.
- **Writes:** only the POST routes, which go through the existing CSRF guard, open a read-write connection.

**Tech Stack:** Python 3.12, FastAPI, Jinja2, SQLite, `fcntl`/`msvcrt` file locks, and htmx 2.0.4 vendored with its
SHA-256 pinned.

**Spec:** `docs/superpowers/specs/2026-11-14-kubedelos-ui-design.md`, section "PR 2: Scans". It also binds the
"Security (always on)", "Which run each page shows", "Look" and "Look, version 2" sections, and the anti-goals.

## Global Constraints

- **AGENTS.md rules:**
  - read-only cluster access, and no Secrets;
  - Trivy pinned, with `--scanners vuln`;
  - credentials never on disk or in logs: an error shown on the page goes through
    `kubedelos.trivy.runner._redact`/`error_cause` first;
  - TDD, one test file per module, Ruff at line length 120, a docstring per module, placeholders only;
  - Conventional Commits, lowercase, with no attribution lines;
  - CHANGELOG `## Unreleased` written by hand.
- **One run at a time, in-process:** a second start while the UI's scan runs is refused with a message, and no second
  thread or run row is created. A CLI scan in another terminal does not block a UI start.
- **Trigger:** UI scans record `trigger = "ui"` and run `kubedelos.scan.service.run_scan` with a cancel event.
- **Context:** a UI scan always scans the UI's context. Its settings are `settings.model_copy(update={"context": <the
  UI's context>})`, never the kubeconfig's current context at click time.
- **Form fields:** namespaces, namespace selector, label selector, image exclusions and package types. Each field defaults
  to the UI's saved settings and is labelled "saved: X".
- **Live progress:** HTMX polls a fragment every 2 seconds. The fragment shows:
  - the phase: `Trivy DB`, `inventory`, `scanning` or `saving`;
  - N of M images;
  - scanned, cached and failed counts from the first image;
  - the image in flight;
  - an ETA once 5 images are done.
- **Cancel:** the readout switches to "stopping after the current image" at once. When the run finishes, the page links
  to its results. Failed and cancelled runs are never linked as results.
- **Run history:** newest first, paged at 25 rows with the real total stated, never silently capped. Each row shows status,
  scope, scan level, images, failures and duration. Only `ok`/`partial` runs link to results.
- **Stale `running` rows:** these are closed as `failed` only when no live process owns them. A CLI scan running in another
  terminal must never be marked failed.
- **Writes:** write routes are POST only and use the existing CSRF guard (`csrf_token` form field). Only they, and the
  stale sweep at UI startup, open a read-write connection. GET pages stay on `open_db` (read-only).
- **HTMX:**
  - **Vendoring:** htmx `2.0.4` is vendored at `kubedelos/web/static/htmx.min.js`, with its SHA-256 recorded and checked
    by a test.
  - **Loading:** it loads on `/scans` only, through `<script src="/static/htmx.min.js" nonce="…">`.
  - **CSP:** the CSP doesn't change. htmx is configured with `includeIndicatorStyles: false`, `allowEval: false` and
    `allowScriptTags: false`, so it needs no inline styles and no eval.
  - **No-JavaScript fallback:** without JavaScript the page still works, with a "refresh" link instead of polling.
- **Look:** the restyled shell (sidebar, chips, cards, `.sev-*`, light and dark themes, 360 px) applies. "Scans" is
  added to the nav after Findings.

## Review Focus

1. **The kubeconfig's current context changes after `kubedelos ui` started.** The UI scan still scans the UI's context.
   (Task 4: `test_scan_settings_pin_the_ui_context`.)
2. **A double-click on Start, or two tabs starting at once.** Exactly one thread and one run row; the second request gets
   the "a scan is already running" message. (Task 5: `test_second_start_is_refused`, and Task 4's lock test.)
3. **Ctrl-C on `kubedelos ui` during a UI scan.** The scan is cancelled (the cancel event is set and the thread joined
   with a timeout), so no Trivy keeps running. A run that still ends up `running` is closed as `failed` by the next
   startup sweep, because its lock died with the process. (Task 4: `test_shutdown_cancels_and_joins`; Task 1:
   `test_sweep_closes_a_run_whose_owner_died`.)
4. **A scan that fails before its run row exists:** an unreachable cluster, a bad selector rejected during inventory,
   or a missing kubeconfig. The page shows the redacted error and lets you start again; it never sits at "starting"
   forever. (Task 4: `test_failure_before_run_row_is_reported`.)
5. **An error that carries a credential**, such as `Authorization: Bearer abc` or a URL with `?sig=`. The page shows it
   redacted. (Task 4: `test_error_text_is_redacted`.)

**Interfaces:**
- Produces:
  - `runlock.hold(data_dir: Path) -> ContextManager[str]`. It creates `<data_dir>/runs/<owner>.lock`, where the owner is
    `secrets.token_hex(16)`, takes an exclusive non-blocking OS lock on it, yields the owner, then unlocks and deletes
    the file.
  - `runlock.is_owned(data_dir: Path, owner: str) -> bool`: True when another open handle holds the lock.
  - `runlock.close_stale_runs(conn: sqlite3.Connection, data_dir: Path) -> list[int]`: the ids it closed.
- **Locking:** POSIX uses `fcntl.flock(fd, LOCK_EX | LOCK_NB)`; Windows uses
  `msvcrt.locking(fd, msvcrt.LK_NBLCK, 1)`. Choose by `sys.platform`.
- **The sweep:** for each `running` row, with an owner that is not owned or a NULL owner (a row from before migration 6,
  when no process could hold a lock), call `Repo(conn).finish_run(id, "failed")` and add the run warning
  `"closed by kubedelos: no live process owned this run"` through the existing `add_warnings` path (or an equivalent
  `run_warning` insert). Rows with a live owner are untouched.

### Task 4: the in-process scan runner

**Files:**
- Create: `kubedelos/web/jobs.py`
- Test: `tests/web/test_jobs.py`

**Interfaces:**
- Produces:
  - `ScanBusy(Exception)`.
  - `JobView(state: Literal["starting", "running", "stopping", "finished", "error"], run_id: int | None, progress:
    Progress | None, status: str | None, error: str | None, eta: timedelta | None)`, a frozen snapshot that is safe to
    render.
  - `ScanRunner(settings: Settings, context: str, *, scan: Callable[..., ScanOutcome] = run_scan, clock=_utcnow)` with
    these methods:
    - `start(overrides: dict) -> None`: raises `ScanBusy` while a job is starting, running or stopping.
    - `cancel() -> None`.
    - `view() -> JobView | None`: None before any job.
    - `shutdown(timeout: float = 10.0) -> None`: sets cancel and joins.
  - `eta(started: datetime, now: datetime, done: int, total: int) -> timedelta | None`: None while `done < 5`.
- **The thread:** `threading.Thread(daemon=True)`. It calls `scan(scan_settings, trigger="ui", on_progress=…,
  cancel=…)`, where `scan_settings = settings.model_copy(update={"context": context, **overrides})`.
- **Finding the run id:** `on_progress` can't see the run id, so read it after `scan` returns from
  `ScanOutcome.run_id`. While it runs, `run_id` is `None` and the page says "Run (starting)". When done, `status` is
  read back from the DB (`get_run`'s status, or a small query) on a fresh connection in the thread.
- **Errors:** any exception sets `state="error"` and `error=error_cause(str(exc))`, which redacts and keeps it to one line.
- **Locking:** a `threading.Lock` guards the state.
