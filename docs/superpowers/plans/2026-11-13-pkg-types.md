# Package types (`--pkg-types`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** users choose whether a scan covers OS packages, application libraries, or both (`os,library`, the default and today's behaviour). Every finding records which class it belongs to. A cached result is never served to a run that asked for a different scan level.

**Architecture:**
- `Settings.pkg_types` is a normalised, sorted, non-empty tuple drawn from `{"os", "library"}`. It becomes Trivy's `--pkg-types`.
- Its comma-joined form, the **scan level** (for example `library,os`), is stored on the run and is part of the cache key.
- The parser keeps Trivy's result `Class` (`os-pkgs` becomes `os`, `lang-pkgs` becomes `library`, anything else is null).
- `TrivyCache` downloads the 1.5 GB Java DB only when `library` is in the scan.

**Tech Stack:** Python 3.12+, pydantic-settings, SQLite migrations in `kubedelos/store/db.py` (`MIGRATIONS`, `PRAGMA user_version`), pytest with `tests/trivy/fake_trivy.py`.

**Spec:** `docs/superpowers/specs/2026-11-13-kubedelos-design.md`. "Scanners: vulnerabilities only" is unchanged; this narrows which packages the vuln scanner looks at. The user decided on 2026-11-13 to add it now, with default `os,library`.

## Global Constraints

- `--scanners vuln` only. `--` stays before the ref.
- The default stays `os,library`, so a user who sets nothing gets exactly today's findings.
- One test file per module, failing test first. Ruff line length 120. Module docstrings stay accurate.
- Schema changes go in a new `MIGRATIONS` entry; existing scripts are never edited.

## Review Focus

1. **Cache poisoning across levels.** A run at `os,library` must never be served a cached `os` result, and the reverse holds too. (Task 2: `test_cache_is_keyed_by_scan_level`)
2. **Equivalent spellings** (`library,os`, `OS, Library`, `os,os`) must give one level and one cache entry, not several. (Task 1: `test_pkg_types_normalised`)
3. **An existing database** (schema version 1, with cache rows and runs) must upgrade cleanly. Old cache rows are dropped, since their level is unknown. Old runs and findings stay, with a null `pkg_types` / `pkg_class`. (Task 2: `test_migration_from_v1_keeps_runs_drops_cache`)
4. **An OS-only run** must not download the Java DB. A later full run on the same cache must download it, and the busy-cache path must not treat "Java DB missing" as an absent DB for an OS-only run. (Task 3: `test_os_only_skips_java_db`, `test_library_run_downloads_java_db_after_os_only`)
5. **Empty or unknown values** (`--pkg-types ""`, `--pkg-types secrets`) exit 2 with a clear message before any Trivy runs. (Task 1: `test_pkg_types_rejects_unknown_and_empty`)

### Task 2: Store the scan level, and key the cache by it

**Files:**
- Modify: `kubedelos/store/db.py` (a new migration), `kubedelos/store/repo.py`, `tests/store/test_repo.py`

**Interfaces:**
- Consumes: `Finding.pkg_class` and `Settings.scan_level` from Task 1.
- Produces:
  - `Repo.start_run(context, trigger, trivy_version, scan_level: str) -> int`
  - `Repo.get_cached(image_key, platform, scan_level: str, max_age) -> ImageResult | None`
  - `Repo.put_cache(image_key, platform, scan_level: str, result) -> None`
  - `run_findings` rows gain `pkg_class`.

Migration 2, appended to `MIGRATIONS`:
```sql
ALTER TABLE scan_run ADD COLUMN pkg_types TEXT;
ALTER TABLE finding ADD COLUMN pkg_class TEXT;
DROP TABLE image_cache;  -- old rows have no scan level: dropping them costs one cold scan, guessing could poison it
CREATE TABLE image_cache (
    image_key TEXT NOT NULL,
    platform TEXT NOT NULL,
    scan_level TEXT NOT NULL,
    trivy_db_version TEXT,
    scanned_at TEXT NOT NULL,
    report_json BLOB NOT NULL,
    PRIMARY KEY (image_key, platform, scan_level)
);
```
`add_result` writes `pkg_class`, and `_RUN_FINDINGS_SQL` selects `f.pkg_class`.

**Interfaces:**
- Consumes: `Settings.pkg_types` and `scan_level` (Task 1), and the repo signatures (Task 2).
- Produces:
  - `scan_image(..., *, cache_dir=None, pkg_types: tuple[str, ...] = ("library", "os"), _groups=None)`. It adds `"--pkg-types", ",".join(pkg_types)` right after the `"--scanners", "vuln"` pair.
